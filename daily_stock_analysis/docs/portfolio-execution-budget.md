# 成交核实与月度预算

本模块复用持仓账本和目标配置引擎，提供人工决策辅助；不连接券商、不发送订单、不自动续期、不产生入金或虚构成交。入口：持仓页的“成交核实与月度预算”。专题文档目前仅中文，新增页面提示提供中英文。

核实成交后，可用[波段收益与持续持有对照](portfolio-performance.md)检查净价差、未恢复股数和经济回本价变化；不通过修改券商成本来模拟降本。

## 1. 成交事实、证据与旧数据兼容

- `POST /api/v1/portfolio/trades` 仍只登记实际成交。新增 `executed_at`（带时区的 ISO 时间，存储为 UTC）、`fee_status=unknown|estimated|confirmed`、`price_basis=execution`、可选 `intent_id`、可选 `request_key`。
- `trade_date` 必须为成交时刻对应的交易所日期；准确时间未知时留空，不将录入时间冒充成交时间。同一持仓（代码、市场、币种）当日所有成交均有准确时间时才按时间回放，否则保留其原流水顺序并披露局限；其他持仓的未知时间不改变该持仓的FIFO结果。本模块不据此推断跨标的日内现金结算顺序。增加更早的成交或修改时间后，重新校验后续流水，拒绝产生历史超卖。
- `price` 只接受真实、未含费的成交单价，不接受券商平均持仓成本或不明含费价格。已有的期初成本继续通过持仓基线录入。
- 费用默认为 `unknown`。旧数据的数值不改写，不追认为已核实。CSV 通用解析器取得的收费为估算，不宣称已覆盖所有收费；没有收费数字时仍为未知。
- `confirmed` 要求显式提供手续费与税费，真实零费用需明确填0。全部交易费税未核实前，快照保留旧账面数值以兼容客户端，但标记 `trade_costs_unverified` 和 `net_pnl_verified=false`。有期初历史缺口或汇率缺口时也不声明全历史净收益已核实。
- `trade_uid` 是券商成交编号，不是委托编号。人工表单另生成请求键，重复提交返回冲突且不增加股数；同一委托的不同部分成交必须有不同的成交标识。没有券商成交编号的跨文件重复识别仍需人工对账，不能声称完全自动去重。
- `PUT /trades/{id}/reconciliation` 核实费用、税费、准确时间，需 `expected_revision` 与 `reason`。修改前后快照写入只追加的审计表，更新缓存并使旧资金确认失效。本轮不开放无痕修改股数、成交价或成本；发现此类错误仍需人工核对，删除旧流水也保留审计证据。

## 2. 预算周期

每个周期绑定一个账户、预算币种、交易所时区、明确起止日期（均包含）、总额度和共享标的。可录一个自然月或自选起止周期，但最长367天。未确认账本完整前余额未知。

- 预算是投入纪律，不是已到账现金、购买力或新增收入；不改变现金账本。
- 周期内所有匹配标的的买入自动纳入核对，不要求先有计划。卖出、股息、入金不增加额度。
- 同账户、相同标的的重叠周期被拒绝。周期到期不自动生成新额度、不追补历史月份，原目标配置对这些标的暂停新增，直到用户建立当前有效周期。
- 旧仓或不属于本轮投入的成交可显式排除，必须有原因，持仓仍保留。已关联计划的成交不允许再排除。
- 跨币种成交必须逐笔确认换算率（预算币种/成交币种）；同币种固定为1。真实费用或换算率缺失时，`remaining_amount=null`，不是零现金，也不是可以使用原始总额度。
- `confirmed_spent` 只合计已核实支出；未核实成交另列 `unresolved_trade_ids`。预算状态包括总额度、已核实支出、委托预留、可新增计划余额和超额金额。
- 确认支出 =（数量 × 成交价 + 手续费 + 税费）× 已确认换算率。费用核实后按新事实重算，不重复扣款。换算率仅用于归属，不改变券商现金或持仓成本。

示例：QQQM与VOO共享本轮额度；本轮之前的VOO通过日期范围或明确排除处理。本轮VOO新增成交只扣一次；HAL往返不会增加QQQM/VOO额度。示例不自动录入个人数据。

## 3. 手工计划与委托反馈

- 先记录 `planned`：保存计划，不预留资金、不登记持仓。计划包含数量、账户原币限价、原币费用预留、规划换算率及带时区的有效期。
- 本阶段委托计划要求账户基准币种与该市场交易币种一致，例如美股账户使用USD；预算本身仍可用CNY。多币种账户不猜测价格单位或资金归属，先通过真实流水核对。
- 用户明确反馈 `submitted` 后，才记录待成交占用。反馈不代表系统批准交易；已经发生的超预算委托仍应如实记录并显示超额，而不是隐藏事实。
- `pending_cancel` 不释放占用。即使有效期已过，只要券商最终状态尚未确认，显示 `expired_pending_confirmation` 并继续预留。研究计划过期不能代替券商撤单回报。
- 确认 `cancelled` 或 `expired` 后仅释放剩余委托占用，不删除已成交部分。
- 实际成交仍通过原成交接口登记并关联 `intent_id`；已有成交可通过关联接口幂等关联，不能为了关联再买入记账。部分成交只扣实际成交量；全部成交由账本推导为 `filled`。
- 未成交占用 = 剩余数量 × 计划限价 + 全额费用预留。剩余部分不为0时保留全部费用缓冲，可能偏保守，不代表券商冻结金额。规划汇率不是实际换汇价。
- 无成交反馈时不能把“已提交”变成“已成交”。关联超过计划股数、错误账户、市场、币种、标的或预算周期会回滚；实际订单改量等复杂情况需人工核对后另行记录，不猜测。

## 4. 与配置建议的联动

- 所有已报送未完成买单（含过期未确认及旧周期委托）按账户原币合计占用，先从账面可分配现金和已核实现金上限扣除，不从资产估值中扣除。
- QQQM、VOO等匹配同一周期的目标，顺序共享剩余额度；某目标不能单独再使用一遍总额度。最终规划上限同时受目标缺口、单批上限、现金预留和周期额度限制；金额向下取到分，不向上突破额度。
- 费用或预算完整性未知时，只保留缺口展示，相关新增金额降级为待核实。资金确认不足时，`funded_amount` 仍为 `null`；不根据预算余额推断已结算现金。
- 多账户总计划中，命中某账户周期时采用保守的共同上限，不假设可跨账户挪用额度。多个配置计划仍是相互独立的方案，建议金额不可叠加执行。
- 预算查询是当前状态，不是任意历史时点的回测接口。带预算账户的历史配置估算暂停新增金额，避免以当前委托状态回填过去。
- 不改变已有现金确认的到期机制和券商结算边界；本阶段不自动推算致富结算规则，不生成做T信号。

## 5. 新接口

以下路径均以 `/api/v1/portfolio` 为前缀，沿用现有管理员认证：

| 接口 | 含义 |
| --- | --- |
| `POST/GET /accounts/{id}/budgets` | 建立明确周期 / 查询当前预算状态 |
| `POST /budgets/{id}/ledger-confirmation` | 确认或撤销本轮账本完整性 |
| `PUT /budgets/{id}/trades/{trade_id}` | 确认换算率或有理由地排除旧仓 |
| `POST /budgets/{id}/intents` | 幂等记录计划，不下单 |
| `PATCH /intents/{id}` | 带版本号、依据记录真实委托反馈 |
| `POST /intents/{id}/fills/{trade_id}` | 幂等关联已有真实成交 |
| `PUT /trades/{id}/reconciliation` | 带版本号、依据核实费用与时间 |
| `GET /accounts/{id}/audit` | 最近200条只追加审计事件 |

周期基本字段本轮不提供修改/删除入口；录入前需核对。资金未知不阻止如实记账，但会阻止将预算解释成可执行金额。

## 6. 升级与回滚

新增四张表：`portfolio_budget_periods`、`portfolio_purchase_intents`、`portfolio_budget_trade_adjustments`、`portfolio_audit_events`。成交表幂等追加 `executed_at`、`fee_status`、`revision`、`intent_id`，不改写旧成交数值。金额使用十进制预算计算；旧持仓会计字段保持原格式。

升级前备份数据库，前后端配套部署。非SQLite部署需另行验证DDL及既有持仓写锁支持。本模块继续复用当前SQLite事务写锁，不宣称新增其他数据库生产支持。

回滚可保留新增表与列，但旧版不认识预算占用、费用证据和按成交时间排序：**先停用配置金额提醒及相关持仓操作，再回滚应用；不可继续使用旧版金额指引，不能删除新表来“恢复”旧预算。** 与期初基线的原有回滚限制同时生效。重启到新版本后重新核对持仓、费用、委托与资金状态。

无新增环境变量，不新增调度任务。本轮只验证程序行为，不证明策略盈利，不保证年度收益。
