# 量化投研系统最终方案

> 文档日期：2026-08-30  
> 工作区：`C:\Users\PC\workStation`  
> 系统定位：每日 AI 投研与决策辅助，不自动交易、不连接券商下单

> 整合状态：2026-08-30 已完成单一主线收敛。`daily_stock_analysis` 为唯一主系统，两个旧项目已完整移动至 `archive`。

## 1. 最终结论

整个工作区应收敛为“一个主系统、两个只读参考来源”：

- **唯一主系统：`daily_stock_analysis`**
  - 承担数据采集、新闻、基本面、技术分析、预测、报告、回测、Web、桌面端、API、调度和通知。
  - 后续所有正式功能只在这个项目中开发。
- **迁移参考：`archive/quant-trading-py`**
  - 作为早期 Python 原型、历史运行数据和旧报告样本保留。
  - 只迁移经核验且主系统缺失的设计、测试或数据；不再独立增加功能。
- **归档参考：`archive/quant-trading-skill`**
  - 这是 Node.js 编写的另一套独立量化分析程序，虽然目录名含 `skill`，但没有标准 `SKILL.md`，不是标准 Codex Skill。
  - 与主系统的数据抓取、技术分析、基本面评分、信号和报告功能高度重复，不应继续维护第二套实现。

因此，不建议把三个目录直接粗暴合并。正确做法是以 `daily_stock_analysis` 为主干，对另外两个目录进行“能力清单对比 → 选择性迁移 → 验证 → 归档”。

## 3. 产品目标与明确边界

### 3.1 产品目标

系统每日为用户完成：

1. 汇总市场、宏观、行业和自选股新闻。
2. 对新闻去重、关联个股、判断新颖度、重要性和可能影响周期。
3. 对具体个股进行商业模式、竞争格局、财务质量、同业和估值分析。
4. 检索历史相似事件，统计事件发生后的收益分布。
5. 结合基本面、估值、事件、市场环境和技术结构，输出多周期概率预测。
6. 提供条件式关注区间、确认条件、失效条件和目标区间。
7. 保存当时的证据和判断，事后评估准确率并校准模型置信度。
8. 输出每日市场报告和个股 Quick / Standard / Deep 报告，并通过 Web、桌面端和通知渠道交付。

### 3.2 不做的事情

- 不连接券商自动下单。
- 不代替用户管理真实账户。
- 不做高频或低延迟交易执行。
- 不承诺收益，不把预测包装成确定结果。
- 不让 LLM 凭空生成财务数字、估值或精确买卖价格。
- 不使用未来财报、修订后数据或未来新闻回测历史判断。

### 3.3 云端盘前与本地深研的执行边界

系统采用两层运行方式，不再让同一份盘前报告在云端和本地重复调度：

| 层级 | 触发方式 | 负责内容 | 明确排除 |
| --- | --- | --- | --- |
| 云端盘前投研 | 工作日北京时间 08:30（A股）、20:30（美股）自动运行 | 最新新闻、宏观、行业、重要公告、市场倾向、候选观察池及后续验证信号 | 完整个股基本面、精确买卖价位、读取本地数据库、自动交易 |
| 手动盘前 Skill | 用户调用 `$a-share-premarket-brief` 或 `$us-stock-premarket-brief` | 在定时任务关闭或额度不足时，按相同证据与输出边界即时生成对应市场简报 | 不恢复定时任务，不读取本地数据库，不执行个股深研 |
| 本地个股深研 | 用户明确指定股票后按需运行 | 多期财务与修订版本、商业模式、同业、估值、历史事件、技术结构、条件式关注/风险/目标区间 | 无明确标的不自动运行，不重复生成云端盘前简报，不连接券商 |

云端报告必须标注数据截止时间、来源和证据边界；本地报告以 `daily_stock_analysis` 的 Standard 契约为统一输出。云端候选观察池只作为本地深研的可选输入，不直接转化为买卖指令。

## 4. 统一目标架构

```text
行情 / 财报 / 公告 / 新闻 / 宏观数据
                  ↓
          证据、来源与时点中心
                  ↓
   公司画像 / 财务标准化 / 新闻事件标准化
                  ↓
 基本面质量  同业比较  估值  历史相似事件  技术结构
                  ↓
       多周期概率预测与风险情景融合
                  ↓
 条件式关注区间 / 确认条件 / 失效条件 / 目标区间
                  ↓
      Quick / Standard / Deep 研究报告
                  ↓
       预测台账 / 结果评估 / 概率校准
```

架构原则：

- 确定性代码负责事实标准化、指标计算、估值、统计和价格区间。
- LLM 负责阅读、归纳、解释、反方审查和自然语言表达。
- 每一个关键结论都能追溯到证据、公式、模型版本和分析时点。
- 数据不足时降低置信度或隐藏相关结论，不以零值或模型猜测补齐。

## 5. 需要补强的正式模块

### 5.1 证据与时点中心

统一新闻、公告和财务数据的证据模型，至少包含：

```text
source_url / source_type / publisher
published_at / effective_at / retrieved_at
report_period / filing_version
market / stock_code / evidence_level
content_hash / raw_snapshot_ref
```

核心能力：

- 一手来源优先，第三方信息只能作为补充。
- 区分发布时间、事件生效时间、财务报告期和抓取时间。
- 新闻转载与内容级去重。
- 保存财报修订版本，禁止以修订后数据覆盖历史回测时点。
- 事实、派生事实、分析判断分层存储。
- 所有历史研究使用严格的 `as_of` 截止时间。

### 5.2 个股企业画像

为每家公司保存可增量维护的长期档案：

- 公司和管理层简介。
- 主营业务、产品、地区和客户结构。
- 行业、产业链位置、周期属性。
- 商业模式和主要利润来源。
- 竞争对手、护城河和市场份额证据。
- 回购、分红、增发、减持和重大资产变化。

企业画像不应每天完整重写，只在事实发生变化时更新版本。

### 5.3 多期财务与财务质量

从当前财务摘要升级为近 5 年、近 8 个季度的三张表标准模型：

- 利润表、资产负债表、现金流量表。
- 营收、利润、自由现金流 CAGR。
- 毛利率、营业利润率、净利率、ROE、ROIC、ROA。
- 经营现金流与净利润匹配度。
- 资产负债率、净负债率、利息覆盖倍数。
- 应收、存货、商誉、资本开支、股本稀释、回购和分红。
- 杜邦分析和主要指标趋势。

增加确定性的异常检测：利润与现金流背离、应收或存货异常增长、利润依赖非经常项目、高 ROE 依赖杠杆、商誉或减值风险等。

### 5.4 同业比较

- 按行业、主营结构和规模选择 3 至 8 家可比公司。
- 比较增长、利润率、现金流、ROIC、杠杆、研发效率和估值。
- 输出同行百分位和差异原因。
- 允许用户调整同业组。
- 保存每次比较使用的同业名单及选择理由。

### 5.5 多模型估值

按公司类型路由估值方法：

| 公司类型 | 推荐方法 |
| --- | --- |
| 稳定盈利 | DCF、PE、EV/EBITDA |
| 高成长 | PEG、PS、情景 DCF |
| 银行保险 | PB、ROE、剩余收益 |
| 高分红 | DDM、股息率历史分位 |
| 周期股 | 中周期利润、PB、EV/EBITDA |
| 尚未盈利 | PS、单位经济、现金消耗情景 |

每次估值必须提供悲观、基准、乐观三种情景，并保存收入增速、利润率、折现率、永续增长率、估值倍数和目标价值等假设。输出合理价值区间和敏感性，不输出伪精确的单一内在价值。

### 5.6 财报复核

财报发布后自动比较同比、环比、连续季度、市场预期、利润率、现金流、分业务表现和管理层指引，并回答：

```text
投资逻辑：加强 / 不变 / 削弱 / 失效
盈利预测：上调 / 不变 / 下调
估值区间：原区间 → 新区间
```

### 5.7 新闻事件智能

将“新闻摘要”升级为“事件记录”：

- 事件类型、关联公司和行业。
- 利多、利空或中性。
- 重要性、新颖度、可信度、预期差。
- 影响的财务指标和影响周期。
- 是否可能已经被市场计价。
- 后续确认或证伪信号。

正式披露、新闻事实、分析师观点和社区情绪必须分开，社区观点不能独立支持财务事实。

### 5.8 历史相似事件研究

检索同公司、同行业及相似市场状态的历史事件，统计事件后 1、3、5、10、20 个交易日的：

- 绝对收益和相对指数超额收益。
- 上涨概率。
- 最大有利波动 MFE。
- 最大不利波动 MAE。
- 样本数、分位数和离散程度。

样本不足时必须显示证据不足，不能由 LLM 补造统计结论。

### 5.9 多周期概率预测

预测对象是收益和波动分布，不是精确收盘价：

- 短周期：1 至 3 个交易日。
- 波段周期：5 至 10 个交易日。
- 中周期：20 个交易日。

输入包括价格、成交量、波动率、市场和行业收益、宏观变量、估值状态、基本面变化、事件强度及历史相似事件。先建立简单统计基线，再让 NeuralForecast 和 Chronos 作为影子模型运行；影子模型积累足够样本并完成校准后，才能进入正式融合。

### 5.10 条件式买卖参考引擎

基本面决定公司质量和价值区间，事件决定逻辑变化，技术面决定时机。统一输出：

- 当前价格与估值状态。
- 第一、第二关注区间。
- 技术确认条件和基本面确认条件。
- 投资逻辑失效条件。
- 风险控制参考位。
- 第一、第二目标区间。
- 预计观察或持有周期。
- 风险收益比。
- 上涨、震荡、下跌概率。

不使用固定的“技术 50% + 基本面 30% + 新闻 20%”简单加权。采用门控逻辑：公司质量不合格限制最高评级；没有安全边际则等待；重大风险或核心假设被证伪则使原逻辑失效。

### 5.11 投资逻辑生命周期

为每只关注股票保存研究状态：

```text
IDEA → WATCHING → ENTRY_READY → TRACKING → INVALIDATED / CLOSED
```

记录关注理由、核心假设、价值区间、催化剂、风险、检查日期、证伪条件、财报兑现情况和最终复盘。该状态表示研究过程，不代表真实持仓或自动订单。

### 5.12 报告契约

提供三种明确、固定的报告，而不是简单改变字数：

- **Quick**：核心事实、方向、估值或价格锚、主要风险、下一步观察信号。
- **Standard**：完整个股研究，作为默认日报内容。
- **Deep**：跨来源核验、多期财务、同业、多估值方法、历史事件、情景和反方审查。

个股 Standard 固定结构：

1. 投资结论。
2. 公司与商业模式。
3. 核心投资逻辑。
4. 财务质量。
5. 竞争和同业比较。
6. 估值区间。
7. 最新新闻与财报变化。
8. 历史相似事件。
9. 多周期情景概率。
10. 催化剂与风险。
11. 条件式买卖参考。
12. 逻辑失效条件。
13. 数据边界和证据来源。

### 5.13 预测台账与校准

每次报告冻结保存当时的数据截止时间、证据快照、预测概率、估值区间、价格区间、周期、置信度和模型版本。后续计算：

- 方向准确率和区间命中率。
- Brier Score 和概率校准曲线。
- 相对指数超额收益。
- MAE、MFE、最大回撤。
- 不同市场、行业、市场状态和预测周期的表现。
- 各模型的边际贡献和失效场景。

现有 `decision_signal_outcome_service.py`、`backtest_service.py` 和 `backtest_engine.py` 应作为扩展基础，不另建平行回测系统。

## 7. 三个目录的收敛方案

### 7.1 `daily_stock_analysis`

- 作为唯一真源和正式运行入口。
- 所有新 Schema、服务、API、Web 页面、报告和测试都落在该项目现有目录边界内。
- 优先复用现有 `data_provider`、`src/services`、`src/repositories`、`src/schemas`、Agent、回测、报告和调度能力。
- 大改前建立版本基线及完整备份，并确认当前压缩包来源和上游版本。

### 7.2 `archive/quant-trading-py`

先生成迁移清单，重点核对：

- 纯新闻日报的输出体验是否有主系统尚未覆盖的细节。
- 五维基本面评分中是否存在值得保留的异常提示，但不保留固定权重总分作为最终决策。
- 历史 K 线、新闻、报告和回测产物是否适合转换为测试 fixture 或历史验证样本。
- 旧回测的佣金、滑点、T+1、止损止盈规则是否有主系统缺失的边界测试。
- 已有未提交改动必须先审阅，不得在迁移或归档时覆盖。

迁移完成后改为只读归档，不再承担定时任务。

### 7.3 `archive/quant-trading-skill`

- 不把它当成正式 Skill 接入。
- 仅参考其简单报告布局或 Node 数据源实现；如果主系统已有同等能力则不迁移。
- 不继续维护第二套新闻、技术指标、基本面和信号引擎。
- 如未来确需 Codex Skill，应另行创建只有 `SKILL.md`、工作流指令和必要脚本的薄封装，调用主系统 API，而不是复制分析逻辑。

## 11. 风险说明

- “量化系统”在本项目中表示可计算、可追溯、可验证的投研系统，不表示自动交易系统。
- 基本面更适合中长期价值和逻辑判断；短期买卖时机仍需结合价格结构、市场状态和事件变化。
- 历史相似事件不保证未来重演，输出必须包含样本量和分布。
- 模型概率需要长期校准，早期不应以高置信度展示。
- 数据源授权、频率限制、商业使用许可和模型权重许可需要在正式部署前逐项确认。
- 所有输出仅用于研究和决策辅助，不构成个性化投资建议。
